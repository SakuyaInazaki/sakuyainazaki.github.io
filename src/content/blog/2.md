我在 9.26 的凌晨一两点钟设置好实验后就去睡觉了。一早上醒来打开电脑，发现各种网站全都无法打开，网页清一色地显示：

> 无法访问此网站
> 网址为 xxx 的网页可能暂时无法连接，或者它已永久性地移动到了新网址。
> ERR_ADDRESS_INVALID

气死我了。我当时想马上修复问题重新跑实验，但由于本地各种 coding agent 全都因为无法联网而无法自动调试，我只能通过复制粘贴的形式古法调试。（微信是少数不多还可以正常工作的通信工具。）

在排除了众多原因后（包括但不仅限于代理配置、DNS cache 等等），基本上确定是本地临时端口耗尽。在 kill 掉具体原因并重启电脑以后，一切恢复正常。

macOS 上每个 TCP 连接都需要从本地临时端口池（49152–65535）里分配一个端口。然而我一直常开的 Codex 疯狂向 Facebook 的 IPv6 地址发起连接，全都卡在 SYN_SENT 状态。这些半开连接每一个都占着本地端口，而 SYN_SENT 状态要等内核超时才会释放，此时端口池就会被填满。等 kill 掉 Codex 并重启后，就会彻底清空内核网络栈，所以 SYN_SENT、TIME_WAIT、CLOSE_WAIT 状态全都归零，端口池也干净了。

不过到现在我也不清楚 Codex 为什么要连接 Facebook。电脑还是要经常重启的，我在出问题的时候已经连续 11 天没有重启了。
